# DCCMCP — X (Twitter) 需求调研题包 v1

> 用途：把下面的问题逐条丢给 Grok（带 X 实时搜索），把结果**原样贴回来**。
> 我会按「痛点 → 功能 → 界面」重新总结成产品需求。
> 目标不是收集观点，而是收集**可引用的原话、链接和频次**——观点只能用来验证方向，原话才能决定做什么。

---

## 0. 给 Grok 的总指令（每次对话开头先发这段）

```
你是一个产品调研分析师。请用 X(Twitter) 实时搜索回答我下面的问题。

输出要求（很重要）：
1. 每条结论必须附**原文引用**（verbatim，不要改写）、作者 @handle、日期、推文链接。
2. 标明互动量（点赞/转发/评论数），按互动量从高到低排序。
3. 明确区分：**用户原话** / **你的推断**，两者不要混在一起。
4. 如果某个问题搜不到足够样本，直接说「样本不足」，不要编造或拿博客/新闻凑数。
5. 最后给出这张表（我下游要用）：

| # | 原文引用 | @handle | 日期 | 链接 | 互动量 | 涉及的软件 | 痛点类别 | 用户类型 | 付费信号 |
|---|---|---|---|---|---|---|---|---|---|

其中：【痛点类别】只能从这几类里选——模型不懂场景 / 生成的代码跑不通 / 破坏性操作无法回退 /
看不到 agent 做了什么 / 不信任权限 / 工具太复杂学不会 / 贵或不知道值不值 / 团队协作与合规 /
其他（写明）。【用户类型】只能选——独立创作者 / 小工作室 / 中大型工作室 TD / 工程师(AEC/制造) /
GIS 从业者 / 学生或研究者 / 其他。【付费信号】写——明确说愿意付 / 已在为工具付费 / 抱怨价格 /
没提。
```

## 1. 核心痛点（最高优先级，先跑这组）

| # | 问 Grok 的话 | 我们要从中得到什么 |
| --- | --- | --- |
| Q1 | 搜索过去 6 个月里，人们抱怨「AI 写的 Blender/Maya/Houdini Python 脚本跑不通」的推文。他们具体卡在哪一步？把原话和链接给我。 | 验证「生成脚本不可靠」这个核心假设，找出**具体失败点**（对象名、上下文、单位、算子状态…），这些直接变成工具的报错设计 |
| Q2 | 有没有人在 X 上说过「让 AI 改了我的工程文件/场景，结果搞坏了，还没法撤销」？中文和英文都搜。 | 验证「回退」是不是真痛点、有多痛。这决定 Checkpoints 是不是我们的主卖点 |
| Q3 | 搜 X 上关于「用 AI agent 操作 CAD / Rhino / Grasshopper / FreeCAD / Revit」的讨论。人们最常吐槽什么？ | CAD 和 3D 的痛点可能不同，决定我们首发哪个方向 |
| Q4 | 搜 X 上 GIS / QGIS / 地理数据处理 + AI 的讨论。他们在做什么、卡在哪？ | GIS 是我们的差异化阵地，样本可能少但价值高 |
| Q5 | 搜「AI 把我文件删了 / 覆盖了 / 改了」这类事故分享（任何软件，不限 DCC）。他们的反应是什么？ | 极端案例最能暴露信任问题，直接决定我们的安全叙事和默认策略 |

## 2. 现有方案为什么不够（竞品/替代品）

| # | 问 Grok 的话 | 我们要从中得到什么 |
| --- | --- | --- |
| Q6 | 搜人们尝试过的「Blender + MCP」「Rhino + MCP」「QGIS + MCP」等。他们装了哪个、体验如何、为什么放弃？ | 找到竞品的**具体失败模式**，以及用户已经形成的预期 |
| Q7 | 人们为了解决这些问题**自己造了什么轮子**？（自己写脚本、自己搭 server、自己写 prompt、录屏教别人） | 用户自己动手做的东西 = 最真实的需求清单 |
| Q8 | 有没有人吐槽「MCP server 太多/太乱/不知道装哪个」？他们怎么选的？ | 决定我们的产品形态：是「一个 app 装 10 个集成」还是「10 个独立包」 |
| Q9 | 搜「Cursor / Claude Code / Codex + 3D 或 CAD 软件」的使用分享。他们实际怎么用的？哪里最爽、哪里最烦？ | 了解他们**已有的工作流**——我们的产品要嵌进去，而不是让他们换工具 |

## 3. 信任与购买（决定定价页怎么写）

| # | 问 Grok 的话 | 我们要从中得到什么 |
| --- | --- | --- |
| Q10 | 搜人们在讨论「愿不愿意让 AI 直接改生产文件」。他们提出的条件是什么？（要先看再改？要审批？要日志？） | 直接变成我们的**策略功能清单**和默认值 |
| Q11 | 搜人们为 AI 开发工具付费的讨论：什么情况下会掏钱、什么情况下坚决不付？他们提到的价格区间是多少？ | 定价与免费/付费的分界线（例如「回退要不要收费」） |
| Q12 | 搜对「订阅制」的抱怨，尤其是开发者工具/插件类。他们能接受什么计费方式？（买断？按席位？按用量？） | 决定计费模式，避免上线后被迫改商业模式 |
| Q13 | 有没有人在 X 上问过「怎么向 IT/老板/客户解释我给 AI 开了写权限」？他们缺什么材料？ | 决定我们要不要做「可导出的安全说明/审计报告」——这是企业版的敲门砖 |

## 6. 追加：三个「反向验证」问题（很重要）

不要只找支持我们的证据，这三条用来**证伪**：

| # | 问 Grok 的话 | 目的 |
| --- | --- | --- |
| Q21 | 有没有人明确说过「我不需要 AI 碰我的 3D/CAD/GIS 文件」？他们给的理由是什么？ | 如果这类声音很强，我们的定位要改成「给 agent 用的只读接口」而不是「让 agent 干活」 |
| Q22 | 有没有人说「现有工具已经够用了」？他们用的是哪个？ | 找到真正的替代品，评估替代成本 |
| Q23 | 有没有人吐槽「本地部署/MCP 太麻烦」？他们希望怎样才对？ | 决定我们是否要做托管/一键安装，以及安装体验的优先级 |
