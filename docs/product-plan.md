## 1. 产品定义

**一句话**：给 AI Agent 用的、可审计可回退的本地控制层——让 Agent 能操作真实的 3D / CAD / GIS / 视觉软件，同时让工程师敢把写权限交出去。

三种形态（同一套内核，逐步长出来）：

| 形态 | 是什么 | 给谁 |
| --- | --- | --- |
| **集成包** | `npx dccmcp-blender serve` + 宿主插件 | 已经在用 Claude Code / Cursor 的技术用户 |
| **控制台 App**（重点） | 桌面应用：状态、审批、回退、审计、统计、许可 | 要「看得见、管得住」的绝大多数用户 |
| **团队服务** | 共享策略、多实例、SIEM 导出、SSO | 工作室 TD、AEC/制造 IT |

🟡 **关键判断**：真正决定付费的不是「能不能连上」，而是「出事了怎么办」。所以控制台 App 不是附属品，是**产品本体**——它承载用户愿意付钱的那部分价值。

## 2. 客户痛点 × 我们的答案（待调研校准）

| 痛点（待验证） | 我们的答案 | 落在界面哪里 |
| --- | --- | --- |
| 模型写的脚本跑不通、靠猜对象名 🔴 | 类型化工具 + 先读后写（`scene.inspect` 类工具） | Tools 页展示可用工具与参数 schema |
| 破坏性操作无法撤销 🔴 | 自动检查点 + 选择性回退（单对象/单文件/整次运行） | **Rollback 页**：时间线 + 影响范围 + 一键回退 |
| 不知道 Agent 改了什么 🔴 | 每次调用记录参数/结果/diff，可筛选可导出 | Sessions + Audit 页 |
| 不敢给写权限 🔴 | 默认只读 + 审批门控 + 拒绝规则 | Approvals 页 + Policies 编辑器 |
| 不知道值不值这个钱 🔴 | 用量与效果统计，试用不阉割功能 | Statistics 页 + Plan 页 |
| 团队里没法统一管理 🔴 | 共享策略、角色权限、审计留存 | Team 页（Studio+） |

⚠️ **付费边界（已确定）**：检查点与回退属于 Studio 及以上；社区版的保护是「默认只读 + 审批门控」。这条已经写进站点，产品实现必须与之一致——**免费版不能出现回退按钮**，否则就是自己打自己。

## 3. 技术栈选型

### 3.1 决策表

| 层 | 推荐 | 理由 | 代价 / 备选 |
| --- | --- | --- | --- |
| 控制台 App 外壳 | **Tauri 2**（Rust） | 安装包 ~10MB、内存低；Rust 侧天生适合做文件快照、哈希、进程与端口管理 | 需要 Rust 能力。若团队只有前端人力 → Electron（生态最省事，代价是 100MB+ 与更高内存） |
| 控制台 UI | **React + Vite + TypeScript + Tailwind** | 与官网同一套设计令牌，视觉统一；生态成熟 | 无 |
| 本地 MCP Server | **Node + TypeScript** | 与官网承诺的 `npx dccmcp-*` 一致；MCP SDK 成熟 | 重 IO 部分（哈希/压缩）走 Rust 侧或 native 模块 |
| Python 侧实现 | **Python 3.11+**（OpenCV、以及部分宿主桥） | OpenCV 生态只能在 Python；宿主插件本身就是 Python | 双语言维护成本 → 用下面的 schema 单一来源解决 |
| **工具契约（关键）** | **JSON Schema 为唯一真相源** | TS 与 Python 都从同一份 schema 生成类型与校验，杜绝两端漂移 | 需要写生成脚本 |
| 宿主插件 | 各宿主原生方式：Blender addon / Maya module / Houdini package / 3ds Max(.NET) / Rhino(Yak,C#) / Photoshop(UXP) / FreeCAD workbench / QGIS plugin / ZBrush ZScript | 只能用宿主自己的扩展机制 | 10 套插件是长期维护成本，建议**先做 3 个**（见路线图） |
| 本地存储 | **SQLite（索引）+ 内容寻址文件仓（zstd 压缩）** | 检查点去重、可定位、易备份；单文件数据库便于迁移 | 大文件要做增量与配额 |
| 审计 | **append-only JSONL + SQLite 索引** | 只追加、可校验、易导出到 SIEM | 需要轮转与留存策略 |
| 策略 | **TOML/JSON + schema 校验 + dry-run** | 可版本化、可评审、可进 Git | 需要可视化编辑器降低门槛 |
| 许可与支付 | **Paddle 或 Lemon Squeezy**（MoR） | 全球税务由对方承担，开发者工具常见；支持订阅+席位 | 费率略高。若只做中国区 → 微信/支付宝 + 自建订单 |
| 账号 | **邮箱魔法链接 + 许可密钥（离线可校验的签名 JWT）** | 不强迫注册；离线/气隙可用 | 不做密码体系，省一大块安全负担 |
| 更新 | **Tauri 签名更新 + stable/beta 双通道** | 灰度发布，出问题可回滚版本 | 需要签名密钥管理 |
| 遥测 | **默认关闭，opt-in，本地优先** | 与「本地优先」承诺一致；统计面板尽量用本地数据 | 会少拿数据，必须靠自愿 |
| 崩溃/错误上报 | 自建接收端点（复用官网 Vercel 函数） | 不引入第三方追踪 | 需要脱敏 |

### 3.2 架构（数据流）

```
宿主软件 (Blender/Maya/Rhino/…)
   └─ 原生插件（只做两件事：暴露宿主 API、连本地 server）
        │  loopback（stdio 或 127.0.0.1 WebSocket，带一次性 token）
        ▼
本地 DCCMCP Server（Node，每宿主一个进程）
   ├─ 工具注册表（读 schemas/*.json）
   ├─ 策略引擎（allow / require-approval / deny + 路径规则）
   ├─ 检查点服务（写前快照 → 内容寻址存储 → 记录 manifest）
   ├─ 审计写入（append-only）
   └─ MCP 端点（stdio / streamable HTTP）
        ▲
        │ MCP
   Agent（Claude Code / Cursor / Codex / 自建）
        ▲
        │ 本地 IPC（控制台只读 + 命令）
   DCCMCP 控制台 App（Tauri）
```

设计原则：
1. **控制台挂了不影响 Agent 干活**；控制台是观察者与决策者，不是单点。
2. **策略在 Server 侧强制执行**，UI 只是编辑器和展示层——绕过 UI 也绕不过策略。
3. **检查点在写操作之前**，不是事后补救。
4. **离线优先**：许可、策略、审计、回退全部本地可用。

## 4. 界面方案（用户要求：容易操作、简单直观、状态/回退/购买/升级/统计齐全）

### 4.1 每屏一个主行动

| # | 屏幕 | 解决什么 | 主行动 |
| --- | --- | --- | --- |
| 1 | **状态总览 Home** | 现在到底在发生什么 | 启动一个集成 / 查看当前会话 |
| 2 | **实时会话 Sessions** | 这一步在干嘛、多久、有没有风险 | 暂停 / 中止本次运行 |
| 3 | **审批 Approvals** | 待批准的写操作（带 diff 与影响范围） | 批准 / 拒绝 / 仅本次允许 |
| 4 | **回退 Rollback** | 出事了怎么回去 | 回退到某个检查点（整次运行 / 单文件 / 单对象） |
| 5 | **审计 Audit** | 上周二到底跑了什么 | 筛选 + 导出 |
| 6 | **工具 Tools** | Agent 到底能做什么 | 按工具改策略（允许/审批/拒绝） |
| 7 | **策略 Policies** | 想要一套可评审的规则 | 保存并 dry-run 验证 |
| 8 | **集成 Integrations** | 装了哪些、版本支不支持 | 安装 / 更新 |
| 9 | **统计 Statistics** | 用了多少、值不值 | 导出或查看明细 |
| 10 | **账户与计划 Plan** | 我是什么版本、还剩多少、怎么升级 | 升级 / 续费 / 管理支付 |
| 11 | **团队 Team**（Studio+） | 谁能做什么 | 邀请成员 / 分配角色 |
| 12 | **设置 Settings** | 传输、存储配额、遥测、更新通道 | 保存 |

### 4.2 易用性「八条铁律」（这几条是产品成败的关键）

1. **默认只读**：第一次打开永远不会有坏事发生，用户才敢点。
2. **说人话**：按钮写「撤销这次运行」而不是 `restore checkpoint`；技术词只在工具详情里出现。
3. **状态永远可见**：顶部常驻一行——宿主在线否 / server 版本 / 当前会话 / 待审批数。
4. **可逆与不可逆视觉分级**：可回退的操作是常规色，不可逆的是警示色 + 明确文案。
5. **空状态即教程**：没有数据时不是空白页，而是「点这里跑第一次只读检查」。
6. **危险操作写清后果与回退方式**，不是干巴巴的「确定吗？」。
7. **审批集中处理**：不打断工作流，可批量审批、可设置「本文件内本次自动批准」。
8. **不装专家也能用**：每个高级功能都有一个「默认能用的版本」，专家再展开细节。

### 4.3 购买 / 升级 / 状态（用户明确点名要齐全）

- **Plan 页常驻**：当前方案徽章 + 席位用量 + 试用剩余天数 + 一个明确的升级按钮（不做多个 CTA 分散注意力）。
- **升级路径无跳转痛点**：应用内点升级 → 系统浏览器打开支付页 → 支付完成 webhook 回来 → **应用自动刷新许可，不用重新登录**。
- **试用到期**：功能降级但**数据绝不删除**（官网 FAQ 已经这么承诺了，产品必须做到：策略、审计、检查点历史都保留，只是不能再新建）。
- **降级**：历史回退记录仍可查看，只关闭「执行回退」与写操作。
- **发票/支付方式**：Paddle/LS 的用户门户直接嵌入或外链，不自己造账单系统。

### 4.4 统计（Statistics）该显示什么

| 指标 | 为什么用户在意 |
| --- | --- |
| 调用总数 / 按软件的分布 | 证明「我确实在用」 |
| 按工具与风险等级的分布 | 发现「我批了太多写操作」（安全教育） |
| 审批通过率与平均处理时长 | 团队效率的真实指标 |
| 回退次数与最近一次回退 | 安全网是否真的兜住了 |
| 失败调用率与 Top 失败工具 | 产品改进线索，也是用户排查线索 |
| 检查点占用的磁盘空间 | 本地优先产品必须让用户掌控存储 |

⚠️ 不要做「节省了多少小时/多少钱」这类拍脑袋指标，一旦被质疑就失去信任。宁可显示真实计数。

## 5. 路线图

| 阶段 | 周期 | 内容 | 完成标志 |
| --- | --- | --- | --- |
| **P0 打通链路** | 0–6 周 | Blender 一个宿主；只读工具 6–8 个；本地 server；CLI；最小策略文件 | 真机上「装 → 连 Agent → 读出真实场景结构」15 分钟内完成 |
| **P1 控制台 MVP** | 6–14 周 | 控制台 App（状态 / 会话 / 审批 / 工具 / 回退）；检查点与回退；许可与支付；第 2–3 个宿主（建议 Rhino + QGIS，一个 CAD 一个 GIS） | 有人**自掏腰包**升级 Studio；回退成功率 100%（在测试矩阵内） |
| **P2 团队可用** | 14–26 周 | 审计 + 统计 + 团队策略 + 多实例 + HTTP 传输 + Skills SDK 公开 | 一个真实工作室用它交付了客户项目 |
| **P3 企业就绪** | 26 周+ | SSO/SAML、自托管/气隙、SIEM 导出、SBOM、签名构建 | 通过一次企业安全审查（真实客户） |

**为什么先 Blender**：插件生态最开放、Python API 最完整、用户量最大、社区最愿意试新东西。Rhino + QGIS 作为第二梯队是因为它们分别代表 CAD 与 GIS 的真实需求，且竞品最弱。

## 6. 北极星指标

| 指标 | 目标 | 说明 |
| --- | --- | --- |
| 首次成功工具调用耗时 | < 5 分钟 | 决定留存的第一道坎 |
| 装完到第一次只读调用的转化率 | > 60% | 低于此说明安装体验有问题 |
| 工具调用失败率 | < 2% | 产品可信度的底线 |
| 回退平均耗时 | < 30 秒 | 安全网的可用性 |
| 试用 → 付费转化 | 待调研后再定 | 现在定目标是自欺欺人 |
| 席位扩张（同账号加人） | 越高越好 | 团队价值被认可的真实信号 |

## 8. 立即要做的三件事（不依赖调研）

1. **把 Blender 的只读工具集定义成 JSON Schema**（`scene.inspect` 等）——这是所有语言与所有界面的地基。
2. **搭起 Server ↔ 控制台的本地 IPC 骨架**（含一次性 token 与断线重连），先用假数据把 6 个核心屏做出来。
3. **确定许可模型的技术形态**（离线可校验的签名许可证 + 试用期状态机），因为支付流程会反向约束账号体系。
